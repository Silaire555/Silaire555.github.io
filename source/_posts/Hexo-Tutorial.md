## 一、准备工作：安装必要软件

你需要安装以下三样东西（全部免费）：

1. **Node.js**（运行环境）  
   - 访问 [nodejs.org](https://nodejs.org)，下载 **LTS** 版本（如 v20.x）。  
   - 安装时一路默认选项，**务必勾选“自动安装必要工具”**（如有）。  
   - 安装完成后，打开命令提示符（Win+R 输入 `cmd`），输入 `node -v` 和 `npm -v`，看到版本号即成功。

2. **Git**（版本管理）  
   - 访问 [git-scm.com](https://git-scm.com)，下载对应系统版本安装。  
   - 安装选项全部默认即可。  
   - 完成后在命令行输入 `git --version` 验证。

3. **文本编辑器**（推荐 VS Code）  
   - 用于修改代码，记事本也可，但有高亮的编辑器更友好。

## 二、安装Hexo并初始化博客

在命令行中执行以下命令（一行一行输入）：

```bash
# 全局安装 Hexo 命令行工具
npm install -g hexo-cli

# 创建一个博客文件夹（例如 myblog）
hexo init myblog

# 进入文件夹
cd myblog

# 安装依赖
npm install
```

现在你的博客已存在，执行 `hexo server`，访问 `http://localhost:4000` 就能看到默认页面。
一些常用的hexo指令（hexo cl，hexo g，hexo s）等可以在网上找到。

## 三、配置GitHub Pages（免费托管）

### 3.1 创建GitHub仓库
- 注册 [GitHub](https://github.com) 账号。  
- 点击右上角 `+` → `New repository`。  
- **仓库名必须为**：`你的用户名.github.io`（例如 `Silaire555.github.io`）。  
- 选择 **Public**，勾选“Add a README file”，点击创建。

### 3.2 安装部署插件（可选，推荐用GitHub Actions自动化）

在博客根目录执行：
```bash
npm install hexo-deployer-git --save
```

修改根目录 `_config.yml` 末尾，添加：
```yaml
deploy:
  type: git
  repo: https://github.com/你的用户名/你的用户名.github.io.git
  branch: main
```

更推荐使用 **GitHub Actions**（无需本地提交`public`文件夹），但初学可先用 `hexo deploy`。

## 四、挑选并安装主题（以academia为例）

笔者使用的主题是 `academia`，一款简洁的学术风主题。但如你所见，笔者目前的博客以及被完全装修成了别的样子。笔者个人认为非学术类博客不太建议使用这个主题，不妨宽松些——选择一些比较大众的主题（如Next），它们往往有成熟的社区生态（好用的插件和教程等）。选择主题的时候记得留意官方文档——包括使用任何插件和工具的时候——官方文档里面会有比较详细的说明书。

### 4.1 安装主题
在博客根目录执行：
```bash
git clone https://github.com/231496/academia.git themes/academia
```

### 4.2 启用主题
修改根目录 `_config.yml`：
```yaml
theme: academia
```

### 4.3 主题依赖安装（可选）
部分主题需要额外渲染器，academia 使用 pug，安装：
```bash
npm install hexo-renderer-pug hexo-renderer-stylus --save
```

## 五、个性化配置：修改主题外观

当然，在完成了基础搭建核心功能后，你可能会想进一步让博客变得独一无二。接下来的内容，我们**只讲思路和原理，不贴代码**，让你理解“为什么这么做”以及“怎么想”，然后你可以根据这些原理自己去尝试或查找具体实现。给各位的建议：善用浏览器搜索、善用AI，哪里跟不上直接甩给Deepseek就行。

### 1. 改变主题的整体外观
- **原理**：Hexo 主题通常由 CSS（样式表）控制。你可以通过覆盖主题的默认 CSS 来修改颜色、字体、间距、圆角等。
- **方法**：创建自己的 `custom.css` 文件，用 `!important` 或更高优先级的选择器覆盖原样式。然后通过 Hexo 的注入器（injector）引入这个文件，这样更新主题时也不会丢失修改。
- **要点**：善用浏览器的“开发者工具”（F12），右键点击任何元素可以“检查”，找到它的类名，然后针对它写样式。
- **动态背景**：使用Three.js 或 Canvas 粒子系统。Three.js听起来学习门槛极高，实则你不学就没有门槛，把你的需求交给ai让它教你即可。


### 2. 修改布局结构
- **原理**：主题的布局由模板文件（如 `.pug`、`.ejs`）决定。你可以复制一份主题文件到 `source/_data/` 或直接修改主题文件夹，但直接修改会在主题升级时被覆盖。
- **更优雅的方法**：使用 Hexo 的 `block` 和 `injector` 功能，在不改动原文件的前提下插入新的 HTML 块，比如在侧边栏添加自己的头像、简介、社交链接等。

### 3. 自定义字体
- **原理**：通过 CSS 的 `@font-face` 引入本地或网络字体（如 Google Fonts 上的霞鹜文楷、思源宋体），然后应用到 `body` 或特定元素。
- **注意**：中文字体文件较大，最好使用 CDN 加载或只保留常用字符集。

### 4. 响应式设计（手机端适配）
- **原理**：使用 CSS 媒体查询 `@media (max-width: 768px)` 为不同屏幕尺寸单独设置样式。例如调整字体大小、隐藏某些装饰元素、改变看板娘大小等。
- **思路**：先保证手机上的基本可读性，再考虑美工。

### 1. 鼠标跟随光晕或彩色拖尾
- **原理**：监听 `mousemove` 事件，动态创建一个绝对定位的 `<div>` 并改变其位置，或者使用 Canvas 绘制粒子数组。
- **效果**：鼠标移动时留下一串渐隐的彩色圆点，或者一个柔和的光圈。你已经实现了后者，可以继续调节粒子数量、颜色、消失速度。

### 2. 点击出现爱心 / 文字特效
- **原理**：监听 `click` 事件，创建一个临时 DOM 元素（如 `<span>`），设置内容（❤️、✨ 或自定义文字），让它从点击位置向上飘动并逐渐透明，最后移除。
- **关键**：使用 CSS `transition` 或 `requestAnimationFrame` 做动画，避免性能问题。

### 3. 页面滚动进度条（显示阅读进度）
- **原理**：监听 `scroll` 事件，计算 `(window.scrollY) / (document.height - window.innerHeight)`，得到一个 0~1 的值，然后改变顶部进度条的宽度。
- **友好提示**：滚动事件触发很频繁，可以用 `requestAnimationFrame` 节流。

### 4. 暗色/亮色模式切换
- **原理**：预先定义两套 CSS 变量（或两套类），通过一个按钮切换 `body` 的类名，或使用 `prefers-color-scheme` 媒体查询。
- **进阶**：将用户的选择存入 `localStorage`，下次访问时恢复。

## 七、插件推荐

Hexo 有大量插件，安装前问自己几个问题：
- 这个插件的功能我能用几行原生 JS 实现吗？（如字数统计、阅读时间）
- 插件是否还在维护？（看 GitHub 最近更新时间、issues 数量）
- 插件是否会影响构建速度？（特别是大量的网络请求或文件处理）
- 插件是否会产生外部依赖（如需要额外注册 API 密钥）？

**优先选择**：轻量、无依赖、纯前端效果的插件（如 RSS 生成、站点地图、压缩工具）。
**谨慎使用**：需要后端支持或第三方服务的插件（如搜索、评论），因为它们可能增加维护成本。

笔者推荐：
hexo-helper-live2d 或者 hexo-oh-my-live2d：我想没有人会拒绝一个萌娘在博客里安家。前者比较古老，已经停止维护。后者仍在积极维护并支持更多版本的live2d。笔者自己选择了helper。注意要写在根目录下的config.yml里，而不是主题文件里的那个。直接改model底下use后面那一串就行。例如：use: live2d-widget-model-miku
hexo-gallery：漂亮的图片画廊，放二次元插画很好看。

## 四、性能优化思路（让博客更快）

### 1. 图片优化
- **原理**：大图片拖慢加载。使用工具（TinyPNG、Squoosh）压缩图片，将宽度限制在 1200px 内，使用 WebP 格式（兼容性可加 fallback）。
- **懒加载**：对于画廊或长页面，让图片滚动到视口时才加载（使用 `loading="lazy"` 属性或 Intersection Observer API）。

### 2. 代码压缩
- **原理**：HTML、CSS、JS 文件中的空格、换行、注释占用带宽。使用 Hexo 的压缩插件（如 `hexo-filter-cleanup`）在生成时自动压缩。
- **效果**：通常能减少 30%~50% 的文件体积。

### 3. CDN 加速
- **原理**：把静态资源（JS、CSS、图片）托管到内容分发网络，让用户从最近的节点下载。GitHub Pages 自带一定 CDN 能力，也可以手动替换一些公共库为 `cdnjs` 或 `unpkg` 链接。

### 4. 减少 HTTP 请求
- **原理**：合并小图标为雪碧图，或将多个 CSS/JS 文件合并成一个。但现代 HTTP/2 下，多个小请求影响不大，重点还是压缩和缓存。

## 八、持续维护与写作体验

### 1. 使用 `hexo-admin` 可视化后台
- **原理**：插件提供一个 Web 界面，在本地运行 `hexo admin` 后可以在浏览器里写文章、上传图片、管理草稿，避免每次都用命令行。

### 2. 自动化部署
- **原理**：设置 GitHub Actions 工作流，每当 `git push` 到特定分支时，自动运行 `hexo generate` 并将 `public` 文件夹推送到 `gh-pages` 分支。这样你只需 `git commit` 和 `push`，博客就自动更新。

### 3. 备份源文件
- **原理**：博客的 `source` 文件夹（文章、图片、配置）是心血，建议将整个 Hexo 项目（除 `node_modules`、`public` 外）也上传到一个私有 GitHub 仓库或使用云备份。
